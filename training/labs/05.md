# 05 - Health and safe rollout

Prerequisite: 04. Goal: diagnose instead of repeatedly restarting.

Tasks:

1. Inspect web.yaml. Explain requests vs limits and readiness vs liveness.
2. Break a rollout:

```powershell
kubectl --context kind-k8training -n k8training set image deployment/web web=nginx:this-tag-does-not-exist
kubectl --context kind-k8training -n k8training rollout status deployment/web --timeout=30s
kubectl --context kind-k8training -n k8training get pods
```

3. Describe a failing Pod. Record the image-pull event and compare Ready old Pods.
4. Repair with `kubectl --context kind-k8training -n k8training rollout undo deployment/web`.
5. Wait for rollout, then run Check.ps1 -Lab 5.

Second experiment: edit deployment/web and change readinessProbe.httpGet.path
to /missing. Inspect Ready counts and events, then restore the path to /.
Pass manually: capture both failure causes, explain why readiness failure does
not itself restart a container, and show the recovered rollout.
Reset if undo history is confusing: apply web.yaml (replicas returns to two).
