# 08 - Incident capstone

Prerequisite: 01-07 complete. Goal: recover an app using evidence.
Timebox: 45 minutes. Driver diagnoses; navigator keeps an incident timeline.

Baseline: apply config.yaml, web.yaml and service.yaml. Wait for rollout.
Keep the Secret, PVC and RBAC from earlier labs. Then inject these lab-only faults:

1. Set web's image to nginx:this-tag-does-not-exist (command in lab 05).
2. Edit Service web: selector app=missing.
3. Edit Deployment web: readinessProbe.httpGet.path=/missing.

Diagnose using get, describe, logs, rollout status and EndpointSlices.
Record a hypothesis and supporting observation before each repair.
Repair each fault with targeted edits/commands; do not delete the namespace.
Use a second terminal for port forwarding and confirm HTTP content manually.

Run Check.ps1 -Lab 8 after recovery. It checks application availability, actual
HTTP access, saved data and RBAC. It does not prove how you diagnosed the faults.

Pass manually:

- Three causes, diagnostic evidence, repairs, and HTTP recovery recorded.
- Both learners explain a cause and its user-visible effect without notes.
- Explain the full browser -> port-forward -> Service/Pod path, and distinguish
  it from an in-cluster DNS request.
- Describe which state is lost when a Pod, namespace or whole cluster is deleted.
- Recreate the application from files in a fresh namespace only as an optional
  follow-up; copy the RBAC subject namespace if changing the namespace.
